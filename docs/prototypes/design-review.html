yiwang.photography 重建：参考案例与设计方案

现站在 Squarespace 上，4 列小图网格把照片当缩略图展示，图片走美国源站，大陆打开要二三十秒。这一页先看别人怎么做（24 个站，三类），再把推荐的版式用你现站的真实照片搭出来，可以点、可以切手机宽度、可以进灯箱。

现状参考案例六条纪律三个方向推荐方案演示待拍板与分期

现状

现站的问题不在"慢"，在"小"。版式把每张照片压到 180 px 宽，加载再快也是在看缩略图。

  • 照片被当缩略图。画廊页是 4 列等宽网格，每张图在 800 px 窗口里只有 180 px，桌面大屏也只有 300 px 左右。
  • 16 个系列，约 250 张。按城市 / 主题命名（Shanghai I、Tokyo Night、San Francisco Sunset…），"一个系列 = 一次旅行或一个主题"的组织方式是对的，保留。
  • Squarespace 已经把图缩到 2000 px 宽再发给访客，10 MB 原图从没真正传出去过。新站用 3200 px 上限反而更大。
  • 第三方依赖：字体从 Squarespace CDN 拉，cookie 横幅，图片走 Fastly 美国节点。这些在大陆都是减分项。
  • /presets 和 /cart 是 Squarespace 的商城，静态站放不下，要单独决定。

六条纪律

从 Linear、Vercel、Anthropic 这类站抽出来的不是视觉，是规矩。它们直接变成新站的设计约束。

一套字体

一款无衬线包揽，或无衬线 UI + 衬线正文。不出现第三种。字体自托管，不拉 Google Fonts，大陆打不开。

三个色

底色、正文色、弱化色。强调色只给链接 hover。照片是唯一的颜色来源。

chrome 退到最小

导航不超过 4 项，页脚一行，没有 hero 文案、横幅、cookie 条、社交图标墙。

留白按比例

图与图、图与边的间距随视口缩放，手机上也不贴边。

动效只在交互处

灯箱开合、图片淡入、hover 出 caption。不做滚动视差，不做入场动画。

性能是设计的一部分

首图不 lazy，其余 lazy；四档 srcset；大陆慢链路上先出文字和版式，再出图。

三个方向

示意图用的都是你现站的照片。推荐 A 为底，把 B 降级成"系列级别的色调"。

A · 档案型 推荐

Yasui / Kawauchi / Kander

米白底，小号排版，首页是系列列表（封面 + 标题 + 年份 + 张数），系列页单列大图纵向排，每张下面一行弱化 caption。

适合：系列会一直增加、题材以城市为主、十年后看不过时。

风险：白底对夜景不友好；比 Instagram 上的观感"安静"。

B · 夜景型

Liam Wong

近黑底，两列大图瀑布流，几乎无缝，颜色自己说话。

适合：tokyo-night、shinjuku、lights、shanghai-ii。

风险：白天的系列（sanfrancisco-sunset、pacifica、aviation）在黑底上发灰；整站黑底手机户外阅读差。

C · 网格型

McKinnon / Instagram

贴边马赛克，所有系列混排，靠 wordmark 和人设撑。

适合：题材杂、更新频繁、把网站当 Instagram 镜像。

风险：每张图都小，正是现站的毛病；要大量裁方。

推荐方案演示

用现站照片搭的可点原型：首页是系列封面墙；进 Aviation 看浅色系列页，进 Tokyo Night 看整页切深色；点任何一张图进灯箱，键盘左右翻、Esc 退出。切到"手机"看 390 px 宽的排法。
